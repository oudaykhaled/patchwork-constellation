# External AI data and budget policy

Policy version: `metadata-only-v2`. External analysis is off by default and still requires an explicit request plus both configured providers. Deterministic grouping and manual corrections remain available when any provider gate fails.

`GroupingService.previewPolicy(snapshot, context)` returns the exact bounded metadata eligible for submission. It includes file IDs/paths, existing island labels, bounded import target IDs and evidence IDs. It sends no source excerpts, diff bodies, commits, repository instructions, credentials or tool definitions. The preview reports excluded-file counts without echoing excluded names. `capabilities().policy` exposes the general disclosure even when analysis is disabled.

Default exclusions cover `.env*`, Git internals, vendor/dependency/build/coverage/generated directories, minified assets, source maps and key-container extensions. `GroupingConfig.excludedPaths` adds up to 64 bounded repository-relative globs; patterns are escaped rather than executed as regex/code. Known credential-shaped paths, IDs and group IDs are excluded. Credential-shaped or control/markup-containing group labels become neutral labels before submission. These guards do not identify every possible secret in arbitrary filenames. Owners must review eligible metadata and configure additional exclusions for their repositories. Files excluded from external analysis keep canonical membership and remain in the graph.

Repository names/paths/labels are untrusted data inside fixed provider request envelopes. They cannot change system instructions, configure tools or choose outbound URLs. Requests use fixed HTTPS OpenAI/TypeSafe endpoints with redirects rejected. Provider labels/rationales/IDs are bounded and validated before becoming proposals; the frontend renders plain text. AI cannot alter source counts or dependency facts.

## Budget and cancellation

Before model discovery, the process atomically reserves the full maximum request envelope, including potential retries. Default limits are five calls per analysis, 100 calls per tenant per hour, two concurrent distinct analyses and no waiting queue. A retry consumes a reserved call. The default hourly token reservation is 1,000,000 estimated tokens; configuration uses `maxReservedTokensPerTenant`. Each request reserves `maxInputCharacters + 3000` as a conservative token allowance. Successful usage settles to reported usage, while failures with unavailable usage conservatively consume their token reservation. Unused call reservations are refunded. A rejected reservation makes zero provider calls.

This is an application request/estimated-token budget, not a verified currency-price cap. Provider account spending limits must be configured independently; tokenization, pricing and account quotas require live-account review. The ledger is process-local and resets after restart. Multiple server processes need shared atomic reservation storage before a multi-instance release.

Equivalent tenant/repository/snapshot/revision/evidence/model requests share one provider job. Each caller cancels its own subscription; the underlying request aborts when the final subscriber cancels. Two callers cannot charge two reservations for the same in-flight key. Provider timeouts, rate limits, invalid output, cancellation and budget exhaustion return a baseline proposal with an explicit status message. Provider retries are bounded and respect short Retry-After values; long delays return a recoverable rate-limited result instead of retrying early.

## Cache, telemetry and deletion

Keys include tenant, repository, immutable context SHA, snapshot and grouping revision, evidence digest, exact configured model names, confidence threshold and explicit policy/prompt/schema/provider-contract versions. Changes to prompt/schema/policy/provider code require a version bump and evaluation before intelligence is enabled.

External proposals are never written to the manual-history file. In memory, cache entries are capped at 64 and proposal entries at 100. Proposals/cache entries logically expire after 15 minutes by default (configurable downward with `proposalTtlMs`). Expired entries are removed on the next proposal registration/request; this is logical access expiry with opportunistic memory cleanup, not a guaranteed physical erasure timer. A process stop clears these stores. `clearExternalData({tenantId, repository?})` immediately removes that scope's cached/proposed data and aborts outstanding calls; accepted manual revisions have a separate retention/deletion policy. Revocation/disconnect handlers should call this hook after current authorization is removed. Budget counters intentionally remain for the rest of their window so reconnecting cannot reset a spending limit.

The optional `onTelemetry` observer receives only outcome, duration, request count, aggregate input/output tokens and cache-hit status. Failed-call token counts are `null` when unknown. It receives no repository/tenant identifiers, raw prompts/source/paths, provider error bodies or credentials. A failing metrics sink cannot interrupt grouping. No telemetry is sent anywhere by default.

TypeSafe's [error rules](https://docs.typesafe.ai/api/errors) distinguish validation/auth/rate/overload failures. Its [legal index](https://docs.typesafe.ai/legal) links account agreements and describes enterprise ZDR as an account-specific offering. Reading that index does not establish this deployment's terms, retention, DPA or ZDR. Provider-side retention/deletion and account-approved data transfer remain unverified; OpenAI's `store:false` request is not a claim of account-wide zero retention.
