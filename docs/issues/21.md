## Remaining-issue follow-up, 2026-11-03

Reviewed against merged product base `2100fbe7d36ed8bdfa86d9129339dbb39a2b8bd7`. The integrated service already rejects response models that differ from the reviewed evaluation manifest, and its cache includes provider, prompt, schema and pipeline versions. The standalone smoke command had a narrower defect: it treated an unversioned generative ID as pinned and could report transport success after that provider returned a different model. It now requires a dated immutable generative model ID, rejects whitespace-only credentials, and rejects actual generative model drift **before** spending a Jev decision request. This strengthens the smoke evidence without enabling intelligence or changing the production release gate.

Verification: **27 focused provider/smoke tests passed**, including zero traffic for mutable model names and exactly two calls before a drift rejection; typecheck and changed-source formatting/lint passed. The actual credential-free CLI returned `blocked` / `INTEGRATION_GATE_REQUIRED`, exit 1. No live request was made. [Machine-readable follow-up](21-followup.json).

Safe configuration discovery checked presence only for `TYPESAFE_API_KEY`, `JEV_MODEL`, `OPENAI_API_KEY` and `OPENAI_MODEL` in process, user and machine environment scopes. All were absent. The main checkout and this isolated worktree had only `.env.example`, with no `.env`. No credential store or unrelated project was searched, and no credential values were printed. These checks establish that this execution has no configured provider account; they do not establish that the owner has no account elsewhere.

The official [models reference](https://docs.typesafe.ai/models), [System One OpenAPI schema](https://api.typesafe.ai/openapi.json), [JavaScript SDK](https://docs.typesafe.ai/sdk/javascript) and [legal index](https://docs.typesafe.ai/legal) were rechecked on 2026-11-03. They confirm Jev is TypeSafe's model, the fixed System One API and account model-discovery route. The public stable version is `jev-1.14.0`; this is a **candidate for evaluation**, not an evaluated pin for this application. Organization quotas require the actual account console, and public legal pages do not establish the applicable account agreement or enterprise retention entitlement.

**Closure remains blocked by original live-account acceptance.** The account owner must configure the two server-side keys outside chat, select immutable models, review the applicable account terms and limits, and authorize the bounded synthetic smoke under those account limits. The existing command above then supplies a redacted transport result. AI-06 separately requires actual quality, cost, calibration and reviewer evidence before the selected models can be enabled. No credentials, model evaluation or policy attestations are invented by this follow-up.
