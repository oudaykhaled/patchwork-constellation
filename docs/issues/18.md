## Observed run

- Windows x64, Node.js 24.22.1, pnpm 11.25.0, Playwright 1.64.1, frozen lockfile. Development frontend/BFF on isolated loopback ports 4418–4420. No external GitHub/model credentials were used by these controlled journeys.
- Installed Chrome **156.0.8078.80**: **18 core/recovery tests passed**. The six new recovery tests were repeated after adding runtime-version reporting and passed. The strengthened source-position test passed after its final assertion change.
- Playwright WebKit **27.2**, revision 2370: **17 passed, one intentionally skipped**. The skipped scenario mutates the real single-user demo revision service and runs in Chromium only; all six new controlled recovery scenarios pass in WebKit.
- Playwright Firefox **157.0**, revision 1555 (package manifest version): executable launch failed with `spawn UNKNOWN` before page creation. One launch attempt failed and the remaining five recovery tests did not run. This is an environment failure, not a browser application result. Prior hosted results belong to the previous implementation and do not certify this new suite.
- `pnpm typecheck`: passed after final source-position assertion.

The first concurrent local run used one shared Playwright output directory and caused two trace-file `ENOENT` failures during WebKit context cleanup. The application assertions had completed. A sequential WebKit rerun with a separate output directory passed all applicable tests. Configurable output directories now prevent independent worktree runners from cleaning each other's artifacts. Keep concurrent output directories separate from the default `test-results` parent as well.

## Reproduce

Run `pnpm install --frozen-lockfile`, then these PowerShell commands from the checkout:

```powershell
$env:PLAYWRIGHT_PORT = '4418'
$env:PLAYWRIGHT_OUTPUT_DIR = '.tmp/e2e-4418'
$env:PLAYWRIGHT_CHROME = '1' # installed Chrome; omit to use Playwright Chromium
pnpm exec playwright test tests/e2e/constellation.spec.ts tests/e2e/recovery.spec.ts --project=chromium --workers=1
```

For WebKit or Firefox, use the matching project name and a distinct port/output directory. `PLAYWRIGHT_BASE_URL` can supply an explicit loopback URL instead; the webServer health URL and port now follow it. Without overrides, CI retains port 4310 and the standard `test-results` directory. Preserve the credential-clearing configuration added by DEL-01/02 when merging this small configuration change.

Screenshots, traces and browser reports are generated by Playwright. Treat traces as controlled-test diagnostics; do not run artifact-producing CI against real private data or production credentials. The CI artifact policy belongs to DEL-02.
