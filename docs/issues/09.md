# Issue #9 — independent PR and commit footprints

Implemented and rechecked against the integrated branch on 2026-11-03. **Recommendation: the scoped code and controlled-fixture acceptance criteria are satisfied, subject to the integrator's review/checks.** This is source-footprint evidence, not an AI-enabled or hosted-release claim.

| Acceptance criterion | Evidence |
| --- | --- |
| Exact compared objects, rule, timestamp, direct changes | Loaded sources expose `baseSha`, `headSha`, `comparisonKind`, `comparedAt`, content-derived `version`, API/Git `fileEvidence`, and upstream `sourceUpdatedAt` when supplied. PRs retain the original branch-tip `baseRefSha` separately from the actual merge base. If neither API nor bounded Git establishes a merge base, the source is explicitly `loaded:false`, `comparisonResolved:false`, has no `baseSha`, no fabricated changes, and incomplete coverage; requested branch pins and an attempt timestamp remain available. The shared contract rejects falsely loading that state. |
| Unique union and overlap | File changes reference canonical node IDs. Confirmed rename aliases resolve later deletions. Independent source-only additions get source-scoped stable identities; equal content is explicitly insufficient evidence of shared ancestry. Unproven lineage produces a coverage notice. No merge-conflict claim is made. |
| Deterministic add/remove and stable IDs | Source loading order is canonicalized. Selection removal retains nodes. Regression tests load independent additions together and in the reverse incremental order and compare per-source file IDs. Geometry remains the graph workstream's responsibility. |
| Independent additions/deletions | Each `source.files` retains its own counts. The existing inspector presents per-source rows and does not add overlapping line totals. Binary Git evidence records `binary: true` with unavailable numeric statistics represented as zero rather than fabricated text lines. |
| Reverts remain touched | Authored root/edit/revert Git goldens prove both activity deltas touch the same file even though the root-to-revert net diff is empty. A loader test preserves both independent deltas and overlap. |
| Force-push/ref changes require refresh | Pinned PR base/head checks reject changed refs with `STALE_SOURCE`; both files pagination and Git fallback recheck refs afterward. An authored Git force-push fixture changes the API head during actual fallback: the loader returns `STALE_SOURCE` and leaves the input snapshot's original pins/files untouched. If refs cannot be rechecked because of a not-found/transient/rate response, exact old objects remain pinned with partial coverage and `refreshRequired:true`. Current metadata access denial and invalid credentials remain errors. |
| Bounded Git fallback | API cap/missing-file evidence and permitted comparison-object failures invoke a fresh **bare** public GitHub fetch of exact objects. A known comparison fetches depth 1. An unavailable merge-base API fetches at most 128 generations per pinned tip and runs actual `git merge-base`, followed by two-object `git diff`. It never treats a branch tip as a merge base. Bounds are a 20-second total process deadline, 4 MiB combined process-output budget, 10,000 changed-file cap and a monitored 64 MiB disk budget. Cancellation kills the child; temporary directories are removed after success/failure. Failed fallback returns explicit partial coverage and does not abort other independent sources. No checkout, imported dependency installation, hooks, submodules, external diff, textconv or inherited Git credential/config environment is used. Origin is fixed to public `https://github.com/owner/repository.git`; redirects are disabled. |
| Cross-branch/fork independence | Actual Git transport goldens create two branch/fork histories with different bases. API comparison responses simulate unavailable/deleted-fork 404 and 403. The fallback resolves each actual merge base independently; it includes only that PR's delta, excludes unrelated base-branch additions, and never synthesizes a merged selection tree. An unresolvable fork object produces an explicitly unresolved source while another selected PR still loads correctly. |

## Explicit limits

- The child process has time/output/cancel bounds and a **polled**, rather than kernel-enforced, disk ceiling. The application runs analysis in its bounded worker thread; no separate OS memory/CPU sandbox is claimed. Deployment-specific capacity evidence belongs to the release performance/security tasks, not a new acceptance condition for this footprint issue.
- The 128-generation ancestry budget can fail on distant merge bases or unavailable objects. Such a source remains explicitly unresolved/partial and can be retried or refreshed. No unlimited ancestry fetch or inferred merge base is claimed.
- Extremely long rename chains and delete/recreate ambiguity remain conservative when ancestry is not established. Content equality is not treated as proof of a shared identity, and ambiguous source-only paths are disclosed in coverage.
- Fallback is intentionally public-only and does not receive installation or user credentials. Private GitHub App integration requires a separate authorized scoped transport before private fallback can be supported.

Primary references checked: [GitHub commit/compare API](https://docs.github.com/en/rest/commits/commits), [Git diff NUL and rename semantics](https://git-scm.com/docs/git-diff), and [Git configuration/environment isolation](https://git-scm.com/docs/git-config).
