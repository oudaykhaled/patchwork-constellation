# Issue #9 — independent PR and commit footprints

Implemented on 2026-11-03. **Recommendation: keep open for the remaining resource/large-history release evidence below.** These changes address source correctness; they do not claim an AI-enabled, private-repository or hosted release.

| Acceptance criterion | Evidence |
| --- | --- |
| Exact compared objects, rule, timestamp, direct changes | Loaded sources expose `baseSha`, `headSha`, `comparisonKind`, `comparedAt`, content-derived `version`, API/Git `fileEvidence`, and upstream `sourceUpdatedAt` when supplied. PRs retain the original branch-tip `baseRefSha` separately from the actual merge base. |
| Unique union and overlap | File changes reference canonical node IDs. Confirmed rename aliases resolve later deletions. Independent source-only additions get source-scoped stable identities; equal content is explicitly insufficient evidence of shared ancestry. Unproven lineage produces a coverage notice. No merge-conflict claim is made. |
| Deterministic add/remove and stable IDs | Source loading order is canonicalized. Selection removal retains nodes. Regression tests load independent additions together and in the reverse incremental order and compare per-source file IDs. Geometry remains the graph workstream's responsibility. |
| Independent additions/deletions | Each `source.files` retains its own counts. The existing inspector presents per-source rows and does not add overlapping line totals. Binary Git evidence records `binary: true` with unavailable numeric statistics represented as zero rather than fabricated text lines. |
| Reverts remain touched | Authored root/edit/revert Git goldens prove both activity deltas touch the same file even though the root-to-revert net diff is empty. A loader test preserves both independent deltas and overlap. |
| Force-push/ref changes require refresh | Pinned PR base/head checks reject changed refs with `STALE_SOURCE`; files-endpoint fallback checks the refs again after pagination. Loaded sources remain immutable until explicit refresh. |
| Bounded Git fallback | API cap/missing-file evidence invokes a fresh **bare** public GitHub fetch of exact objects followed by direct two-object `git diff`. It has a 20-second total process deadline, 4 MiB combined process-output budget, 10,000 changed-file cap and a monitored 64 MiB disk budget. Cancellation kills the child. A temporary directory is removed after success/failure. A failed fallback retains API results with explicit partial coverage. No checkout, imported dependency installation, hooks, submodules, external diff, textconv or inherited Git credential/config environment is used. Remote origin is fixed to public `https://github.com/owner/repository.git`, and HTTP redirects are disabled. |
| Cross-branch/fork independence | Each PR's merge-base/head pair is handled separately. No selected-source merged tree exists. Tests use differing base/head pairs in one snapshot. GitHub's repository compare API remains the authority for the merge base. |

18 tests pass, including actual Git-authored root, edit, revert, rename, deletion and two-parent merge history. The merge loader explicitly compares first parent to merge rather than trusting combined commit presentation. API replays cover a 3,001-file PR cap, the 300-file merge comparison ceiling, bounded fallback failure and force-push rejection. NUL parsing tests cover binary statistics, tab/newline names, malformed statistics, invalid UTF-8, unsafe paths and changed-file overflow.

The smoke took approximately 1.9 seconds on this Windows host. This small smoke is not large-repository capacity evidence. An initial smoke used a mistyped nonexistent base SHA and failed safely with `GIT_FALLBACK_FAILED` before the corrected run.

## Remaining gates

- The child process has time/output/cancel bounds and a **polled**, rather than kernel-enforced, disk ceiling. It does not claim an OS memory/CPU sandbox. The delivery/security workstream must apply and verify deployment-level process/container memory, CPU and storage limits before accepting arbitrary large public repositories in a hosted release.
- Full large-history/fork staging evidence is still needed: actual API-cap repository, unavailable fork objects, very long rename chains, delete/recreate ambiguity, force-push during fallback, and sustained memory/disk/failure measurements. The code does not infer missing ancestry from content equality.
- If GitHub cannot establish a PR merge base at all, the existing recoverable API error is retained; the tool does not silently substitute the branch tip or invent an exact comparison. No arbitrary-depth ancestry fetch is claimed.
- Fallback is intentionally public-only and does not receive installation or user credentials. Private GitHub App integration requires a separate authorized scoped transport before private fallback can be supported.

Primary references checked: [GitHub commit/compare API](https://docs.github.com/en/rest/commits/commits), [Git diff NUL and rename semantics](https://git-scm.com/docs/git-diff), and [Git configuration/environment isolation](https://git-scm.com/docs/git-config).
