## Integrated selected-head and hierarchy validation

Follow-up after merging integration commit `94467b0`:

- `ChangeSourceSchema` explicitly validates import edges, aggregate/per-file import coverage and the pinned analysis head. These fields no longer bypass validation as unknown passthrough values.
- Source-head edges must remain outside context edges. Their endpoints must identify visible context/source-only files, and the importer must be an analyzed, non-deleted directly changed file. Renamed importers use the source comparison path while preserving their existing file ID.
- Each observed edge requires matching parent source ID, selected-head provenance, exact head/context SHAs, importer path, resolver, line and specifier. Foreign snapshot IDs, cross-layer ID collisions and dangling endpoints are rejected.
- Per-file coverage describes each changed file once with a supported status; successful parsing requires its pinned head even when no imports exist. Explicit unparsed budget and failed-layer fallbacks remain valid without invented edges.
- Nested canonical hierarchies require a version and validate unique IDs/paths, physical ancestry, memberships, reciprocal component membership, group/folder references and exact finite counts. Optional hierarchy data is checked when present, including against visible snapshot file paths.
- The source-head producer uses the exported coverage enum/type instead of an unchecked string cast.

Verification on the merged branch: `pnpm typecheck`, `pnpm test` (198 passed, one database integration skipped), `pnpm build`, and `git diff --check` passed. ## Canonical file-fact adoption

The final acceptance audit removed the remaining untyped file metadata gap. `fileKind`, `presence`, inventory `status`, `importCoverage`, `importReasons`, `externalImports` and `unresolvedImports` are now required shared-schema fields. The canonical classification matches actual producer values: file, binary, generated, symlink, submodule, LFS pointer or explicitly unknown. The old optional `fileType` name remains a validated deprecated alias; classification authority is `fileKind`.

Per-file import references validate relation kind, line, specifier, reason and optional import/require mode. Invalid statuses/classifications, malformed reasons, impossible sizes and falsely complete unresolved imports fail the runtime boundary. A missing fact is rejected rather than silently defaulted to successful parsing.

`nodeForPath` explicitly creates unknown/partial inventory facts with a reason. Static analysis replaces these with verified classification and parser coverage, including special-file exclusions and unresolved/external metadata. Source-only ghosts remain unknown/excluded at the context layer; their add/rename/delete status and any source-head dependency evidence remain in the separate source comparison layer. Context edges require analyzed context-file coverage.

Synthetic fixtures now explicitly declare their scoped dependency coverage through `authoredFileFacts(coverage)`. The helper requires a coverage argument and labels its author-declared synthetic provenance; it is never used for real repository analysis. A new regression validates actual `buildStaticGraph` output through the same file and full graph schemas, including unsupported languages, symlinks, submodules, LFS, binary/generated content and unresolved imports. Another regression proves source-only add status does not get copied into canonical context facts.
