# #3 · DATA-01: graph contract hardening

Implemented in an isolated worktree against `a514823` on 2026-11-03. This report does not close the GitHub issue.

| Acceptance criterion | Evidence |
| --- | --- |
| Pinned context independent of overlays | Required context ref/SHA fields; GitHub snapshots reject non-object SHAs. Existing analysis integration pins default `main` at start and source-selection helpers do not modify context, grouping, or file IDs. |
| Exact comparison pair per source | Every snapshot source now requires base/head and compatible comparison kind at runtime. GitHub pairs require 40- or 64-digit object SHAs; commit head must match its commit SHA. Picker types retain optional comparison fields to permit intermediate discovery data; only complete snapshots pass the boundary. |
| File/edge metadata and provenance | File type, presence, per-source status, ancestry and import direction/evidence are typed fields. GitHub edges require object evidence, resolver and a pinned context or explicitly attributed source-head SHA. Foreign source/snapshot IDs, mismatched importing paths and unpinned evidence fail validation. Optional enrichment remains optional for existing authored fixtures; a missing type must not be interpreted as successful parsing. |
| Explicit coverage | All five states are represented. Non-complete states require a reason; analyzed counts cannot exceed totals. Unknown/unsupported imports remain coverage limitations, not negative dependency facts. |
| Distinct direct/overlap/neighbor data | Added serializable `SelectionFootprintSchema` and `createSelectionFootprint`. Direct files and dependency-only neighbors have distinct flags. Counts separately report changed files, overlapping files, participating overlapping sources and dependency neighbors. Count/membership contradictions are rejected. Existing Set/Map presentation interface remains for compatibility. |
| One schema source | Zod schemas infer TypeScript types. `graphSnapshotJsonSchema()` emits the structural JSON Schema from the same runtime schema. Cross-reference and semantic invariants additionally run at the Zod boundary; JSON Schema alone is insufficient. Added a versioned shared `AnalysisJobSchema` with progress/date/terminal-state checks. |
| Canonical fixture | The same 212 nodes and 235 edges validate; three PRs give 68 changed/14 overlapping files and two PRs give 57/2. Selection does not mutate the snapshot. Two synthetic commit object literals were corrected to exactly 40 digits without changing IDs, labels or expected sets. |

Additional guards reject duplicate source change identities, asymmetric node/source membership, duplicate IDs, dangling references, unsafe relative paths, inconsistent repository identity, group cycles, and impossible add/delete counters. Unversioned snapshots are intentionally rejected; old persisted data must be reanalyzed or explicitly migrated, never silently assigned a version.

## Integrated selected-head and hierarchy validation

Follow-up after merging integration commit `94467b0`:

- `ChangeSourceSchema` explicitly validates import edges, aggregate/per-file import coverage and the pinned analysis head. These fields no longer bypass validation as unknown passthrough values.
- Source-head edges must remain outside context edges. Their endpoints must identify visible context/source-only files, and the importer must be an analyzed, non-deleted directly changed file. Renamed importers use the source comparison path while preserving their existing file ID.
- Each observed edge requires matching parent source ID, selected-head provenance, exact head/context SHAs, importer path, resolver, line and specifier. Foreign snapshot IDs, cross-layer ID collisions and dangling endpoints are rejected.
- Per-file coverage describes each changed file once with a supported status; successful parsing requires its pinned head even when no imports exist. Explicit unparsed budget and failed-layer fallbacks remain valid without invented edges.
- Nested canonical hierarchies require a version and validate unique IDs/paths, physical ancestry, memberships, reciprocal component membership, group/folder references and exact finite counts. Optional hierarchy data is checked when present, including against visible snapshot file paths.
- The source-head producer uses the exported coverage enum/type instead of an unchecked string cast.

Verification on the merged branch: `pnpm typecheck`, `pnpm test` (198 passed, one database integration skipped), `pnpm build`, and `git diff --check` passed. New malformed-layer and nested-hierarchy regressions cover foreign evidence, unsupported statuses, missing pins, incorrect counts, duplicate coverage and dangling references.
