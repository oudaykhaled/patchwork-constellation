# UX-02 / #14 — source selection and shared views

Reviewed against the published issue on 2026-11-03. This patch fixes selection lifecycle and restore gaps in the working Constellation UI; the first contribution-grid direction remains absent.

| Acceptance | Implementation and evidence |
| --- | --- |
| Pinned default or explicit context | The existing analysis API pins and returns the context SHA; the header displays ref/SHA. Sharing serializes that SHA, while source changes only call `/api/sources`. Context changes call `/api/analyze` explicitly. The restored-source browser test asserts a pinned context in the URL. |
| Multiple PRs/commits with keyboard | Native checkbox controls remain keyboard operable. The patch remembers each mode's selection, including the deliberately empty selection, and caps selection at the API's 20-source bound. Browser tests exercise both modes. |
| Exact unique/overlap counts | Counts use canonical node IDs and source membership sets, never line totals. Existing canonical browser tests prove 68/14 → 57/2, with a separate 24/4 commit footprint. Pending/failed requests display unavailable counts instead of an apparently complete provisional footprint. |
| Per-file source identity/status | The existing inspector consumes canonical `FileChange.fileId` and status. Deep links now retain source-only selected file IDs until the loaded footprint adds those files, rather than silently losing the inspector target. |
| Zero sources | `sources=` is distinct from an absent parameter. It reopens the context-only view with the selection prompt, survives reload and is remembered across mode changes. |
| Recoverable errors and partial data | Server messages remain visible; selection failure has retry and explicit analysis refresh actions. Missing saved IDs produce an actionable message rather than unrelated default PRs. Discovery distinguishes unloaded footprints from zero-file results. Existing partial coverage remains visible. Rate exhaustion and revoked access are covered by browser fixtures. |
| Cancelable/latest request wins | Each source update gets an AbortController, selection generation and context epoch. Newer work aborts earlier work; context/grouping changes invalidate it. Cancel restores the last confirmed selection. Browser fixtures delay obsolete work, then assert that it cannot replace the latest result. |
| Geometry/camera/focus | Selection changes retain snapshot identity and do not issue Fit. Existing camera preservation regression passes. Layout worker/pin work belongs to GRAPH-02. |
| Share IDs and camera | `selection-state.ts` serializes repository, immutable context, source IDs, file ID and finite bounded camera. Restoring an ID outside the initial discovery page scans at most ten pages (300 recent records) before reporting that it cannot resolve the ID. It never silently changes to the default sources. App consumes GRAPH-03's `initialCamera`/`onCameraChange` interface; writes are throttled to 200 ms, and Save view flushes the current camera. Reopening calls the analysis API, preserving its authorization boundary. |
