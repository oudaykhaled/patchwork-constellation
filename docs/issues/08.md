# DATA-03 / issue #8 evidence

Reviewed 2026-11-03 against the original issue contract. This change strengthens the existing public-repository gateway without changing selected-source semantics.

## Implemented

| Acceptance criterion | Evidence |
| --- | --- |
| PR/commit pagination | `GitHubClient.page()` preserves filters, replaces page/per-page query values, validates page bounds, retains GitHub's authoritative Link metadata through conditional responses, and never follows supplied origins. Existing `listRepositorySources` maps pages to source-picker choices. |
| Immutable and mutable cache | Credential-hashed, repository/URL-specific bounded cache; immutable tree/blob requests and raw sources include pinned SHA in the key. Raw source keys also include the byte bound. Mutable cache entries retain ETags and are conditionally revalidated. `invalidateGitHubRepositoryCache` expires only mutable metadata for explicit refresh/webhook integration. |
| Truncated tree | Existing analyzer reports visible partial coverage when recursive tree is truncated; gateway emits a structured `recursive-tree-truncated` event. No complete-tree claim or unbounded recursive traversal is made. |
| File caps | Existing analyzer uses the dedicated PR-files endpoint for large comparisons and detects the 3,000 PR-file ceiling. Comparison pagination is not interpreted as further file pages. Gateway emits `comparison-file-cap` at 300 comparison files and `pull-file-cap` for a full 30th 100-file PR page. |
| Retry and errors | Maximum three configurable retries, default two, with a cumulative default 5-second wait budget and hard 30-second maximum. Retry-After seconds/HTTP dates and exhausted-quota reset times take precedence; an indicated wait beyond the budget produces RATE_LIMITED with retry guidance rather than an early retry. Network/transient 5xx use bounded exponential delays. 401, ordinary 403, 404, rate limiting and network failures have distinct codes. Headerless secondary-rate-limit messages are classified without exposing their bodies. |
| Request deduplication | Same credential/request shares transport. Each subscriber can cancel independently; transport is aborted when no subscribers remain. Requests for each credential are serialized, queued work is bounded to 64 and canceled queue entries are removed. No imported repository code executes. |
| Telemetry | Optional typed callback receives request/cache/dedup/retry/coverage events with status, retry timing and numeric quota headers. Events omit URLs, repository/file names, tokens, bodies and error text. Observer failures cannot break ingestion. |

## Remaining verification boundaries

- Queue/cache are process-local. They deduplicate viewers sharing a BFF/worker process; multiple independent worker processes do not share an installation quota coordinator. The auth/job workstreams must supply any distributed installation coordination required for a hosted edition.
- UI loading-state and filtering journeys belong to UX-02; this change does not independently establish browser acceptance.
- The cap/truncation paths remain visibly partial. A Git fallback is separate work, and API-only visibility cannot prove a complete 3,001-file change set.
- This scoped replay run does not establish live GitHub App revocation/access behavior or hosted quota measurements. Private raw content access remains intentionally unauthenticated; the App flow needs an authorized API blob retrieval path.
- New cache invalidation hook is implemented and tested; calling it from verified webhook ingress is DATA-08 work.

Recommendation: retain issue #8 open until distributed-installation coordination and the integrated picker/cap scenarios are reviewed with DATA-02/04 and UX-02. The gateway's implementation gaps above are fixed; no external issue state was changed.

## Primary API references checked

- [GitHub REST best practices](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api): serial requests, conditional requests, Retry-After/reset and bounded increasing delays.
- [Git trees](https://docs.github.com/en/rest/git/trees): truncated recursive trees require subtree traversal or explicit partial results.
- [Commits](https://docs.github.com/en/rest/commits/commits): comparison files appear on the first page, while commit-file pagination has a separate limit.
- [Pull requests](https://docs.github.com/en/rest/pulls/pulls): PR files are a separate paginated endpoint.

The existing REST version pin remains `2022-11-28`; API-version migration is separate from this behavioral correction.
