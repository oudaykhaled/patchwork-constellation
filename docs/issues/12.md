## API paging

1. Poll `/api/jobs/:id?repository=owner/repo&includeSnapshot=false` until ready/partial.
2. Follow `graphUrl` for metadata and coverage. Retain its `version`.
3. Page groups/nodes/edges with `limit` (groups ≤200, nodes ≤500, edges ≤1000), `version` and the returned `nextCursor`. Preserve `groupId`/`kind` across pages. A changed revision returns `409 STALE_VERSION`; restart from metadata.
4. Nodes are paged independently before edges; global edges reference IDs in the complete snapshot node set. Group-filtered edges reference only the filtered group. Cross-group exclusions are counted rather than presented as a complete dependency subgraph.

Chunks target at most 480KB of items, leaving room below a 512KB full-response budget. Oversize individual items or file details produce `413 PAYLOAD_LIMIT`. Group summaries are capped and fully available through group paging. No source contents are exposed by these endpoints.

## Durable recovery and authorization integration

`AnalysisJobs(store, admission, runner, save, credentials?)` rechecks optional server-only credentials before **each** execution attempt. `submit(scope, pinnedInput)`, `get(id, scope?)`, `cancel(id, scope?)` and `startRecovery(ownerId)` are the integration boundary. Never store an installation token in job input. Authorized users reconnecting to a persisted job activate recovery for their owner; the credentials callback must recheck live repository access and fail closed when access has been revoked. The callback must also preserve the owner scope when saving results; AsyncLocalStorage request state does not survive a background recovery tick.

The PostgreSQL store uses transaction/advisory locks, owner-scoped discovery, `FOR UPDATE SKIP LOCKED`, conditional lease heartbeats/progress/completion, and bounded retention. A restarted worker redoes analysis of its pinned context; it does not resume a half-written AST or import transient worker memory. Snapshots only publish after validation. Explicit refresh/source reconciliation remains separate from changing immutable context.

## Integrated authorization and revocation follow-up

The merged server now uses DATA-02 credentials for ref pinning, every worker attempt, and result publication. Background callbacks explicitly enter their stored owner scope rather than inheriting request AsyncLocalStorage. All job wire views runtime-parse the shared `AnalysisJobSchema`. Queue keys import the actual analyzer and deterministic grouping rules versions. Caches, snapshot writes, source requests and grouping services are isolated per server and owner. `/api/graphs`, `/api/files`, grouping/current/diff/reject/policy and result routes independently enforce owner/repository access. Mutation preconditions are required, and every grouping operation receives the same tenant ID.

`purgeRepository(scope)` advances an owner/repository epoch synchronously, aborts/fences analysis/source/provider work, waits for older snapshot writes, removes exact repository grouping histories through the real durable CAS service, then deletes scoped jobs/snapshots/caches. Late queue completions, source overlays and manual writes cannot republish after deletion. Tests prove these actual paths, including an already-started delayed grouping write. Per-owner durable history paths preserve isolation; normal local startup defaults to `.cache/grouping.json`, explicit empty storage disables it, and tests remain isolated. The configured AI exclusions accept comma/newline-separated `AI_EXCLUDED_PATHS`; POST `/api/grouping/policy` returns only eligible bounded metadata without invoking a provider.
