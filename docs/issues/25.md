# #25 — grouping review and explanations

Implemented in the isolated `fix/issue-25` worktree on 2026-11-03. This report covers UI behavior; it does not substitute for the live-provider evaluation in #21/#26 or durable-service acceptance in #24.

| Acceptance criterion | Implementation and evidence |
| --- | --- |
| Current grouping source | The panel names deterministic folder/module rules, deterministic code analysis, approved AI + Jev, or manual override. It reads the accepted revision, provenance and `canUndo` from `/api/grouping/current`; it discloses memory versus server-file persistence. Manual source takes precedence over retained AI labels. |
| Proposed island name, evidence and uncertainty | Each island has its own expandable review. Decisions display readable file paths and observed import relationships, rationale, optional model confidence, model versions and separate evidence-coverage counts. Missing confidence is stated. Model confidence is explicitly not measured accuracy. No raw model traces are rendered. |
| Membership and movement preview | Every changed membership is listed. A cancellable layout worker uses the active settled layout and `previewLayoutChanges` from #13 to draw hollow current positions, filled proposed positions and movement lines. These lines are labeled as movement, not imports. Preview never installs proposed membership or changes the active camera. |
| Reversible corrections | Rename/merge/split controls and the existing inspector move action call versioned mutation endpoints. Initial and reopened panels load the current revision; writes send `expectedRevisionId`. Conflicts retain the active map and offer explicit latest-revision review. `canUndo` avoids assuming that every audit parent represents an available undo step. |
| Provider failure and invalid output | Baseline responses have an explicit retained state. Malformed response shapes become a readable retained state; foreign file/island/evidence IDs disable Apply. Disabled, timeout and budget statuses cannot replace the active grouping. |
| Generated summaries and factual invariants | Generated names and explanations are labeled, escaped React text. Proposal inspection checks complete file membership against the current snapshot. Grouping adoption updates groups and memberships while retaining the current source overlay, paths, edges and source-change counts. |
| Apply/undo revision and layout | Apply/undo use #24's revision endpoint contract. The renderer's #13 structural layout cache retains prior settled layouts, and preview uses actual active positions through `onLayoutReady`. The combined server/renderer revision round trip remains an integration check after cherry-picking #13/#15/#24. |
| Why this group from island and file | Focused-island and selected-file actions open the same readable explanation. Physical presentation groups use their actual displayed files. Current rules/manual/AI provenance is distinguished; persisted decisions/models from #24 are displayed when available. Otherwise the UI states that no persisted model rationale exists and presents observed paths/import counts. |
