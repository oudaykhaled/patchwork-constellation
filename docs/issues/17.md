## Hover-content follow-up

The graph's file tooltip previously disappeared as soon as the pointer left its circle and could not receive pointer input. Escape could clear an unrelated file selection instead of dismissing hover content.

- Tooltip content accepts pointer hover. Its anchor stays at the circle's entry point rather than chasing the pointer. A bounded 220ms gap bridge protects movement into the tooltip, including crossings near neighboring file hit areas. Hovering either the trigger or content keeps it visible without a duration limit.
- A capture-phase Escape listener dismisses the tooltip even when keyboard focus stays in another control. That Escape preserves current file/source selection, camera and focus; another Escape can perform the normal inspector dismissal. The same trigger remains suppressed until the pointer leaves it. Native modal Escape retains priority over a tooltip behind its inert backdrop.
- Leaving both trigger/content hides the tooltip after the bridge. Layout/scope changes reset hover, and effect cleanup removes the listener and cancels its one bounded timer.
- `graph-tooltip.spec.ts` uses actual mouse movements, the pure graph layout and live camera attributes. It rejects points obscured by DOM controls. Four production checks pass across Chromium and WebKit: circle-to-tooltip transit/dwell/leave/Escape, and dismissal while a file is selected with source/camera/focus invariants, including modal Escape priority. The existing accessibility/navigation suites also pass 17 Chromium/WebKit checks with one intentional Chromium-only touch-injection skip.

This closes the observed hover-content implementation defect. Human assistive-technology, text magnification and task-review gates above remain unclaimed.

The inspector/tooltip browser journey waits for the inspector's intended close-button autofocus before deliberately focusing search. Inspector visibility can precede its animation-frame focus transfer. The journey asserts search focus both before Escape and afterward, retaining the focus-preservation check without racing that opening transfer. This synchronization passes six repeated WebKit runs of both tooltip cases (12 checks, two concurrent workers) on the local production build; hosted Linux verification remains a separate CI result.

## Independent accessibility follow-up after PR #32

The 2026-11-03 follow-up against merged base `2100fbe` found a real keyboard/ARIA mismatch: search exposed listbox options without a related combobox, active option or arrow navigation. Source mode selection was only a visual class. Both are fixed:

- Search now exposes its expanded/list relationship and active descendant. Arrow Down/Up traverse suggestions in rendered order while DOM focus remains in the input; Enter opens the active file/island. Input editing and modified browser shortcuts remain native. Options are outside the Tab sequence and the active choice has an explicit outline as well as a tinted background.
- Escape while suggestions are open clears them without closing an unrelated inspected file. A later Escape retains the existing detail-close behavior. Empty results are a named status, not a listbox without required children; no nonexistent active option is referenced.
- PR/commit source-mode buttons expose their pressed state. Existing exact footprint counts and separate remembered selections are preserved.
- Expanded axe coverage found selected search metadata at 4.21:1 contrast against its active background. The existing readable muted token replaces the low-contrast small-text color, including hover/selected states; forced-color styling uses system colors.

The focused regression initially failed on the missing combobox. New matching/empty-result scans then independently caught the contrast and empty-listbox problems. After the fixes, **18 production checks passed**: all five accessibility journeys plus all four immutable file-inspector/evidence journeys in installed Chrome and WebKit, one worker, loopback port 4517. Typecheck, production build, focused format/lint and diff checks passed. These are functional/accessibility checks, not a performance reference or a claim of new Firefox evidence; the combined hosted matrix remains the integrator's check.
