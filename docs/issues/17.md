## Hover-content follow-up

The graph's file tooltip previously disappeared as soon as the pointer left its circle and could not receive pointer input. Escape could clear an unrelated file selection instead of dismissing hover content.

- Tooltip content accepts pointer hover. Its anchor stays at the circle's entry point rather than chasing the pointer. A bounded 220ms gap bridge protects movement into the tooltip, including crossings near neighboring file hit areas. Hovering either the trigger or content keeps it visible without a duration limit.
- A capture-phase Escape listener dismisses the tooltip even when keyboard focus stays in another control. That Escape preserves current file/source selection, camera and focus; another Escape can perform the normal inspector dismissal. The same trigger remains suppressed until the pointer leaves it. Native modal Escape retains priority over a tooltip behind its inert backdrop.
- Leaving both trigger/content hides the tooltip after the bridge. Layout/scope changes reset hover, and effect cleanup removes the listener and cancels its one bounded timer.
- `graph-tooltip.spec.ts` uses actual mouse movements, the pure graph layout and live camera attributes. It rejects points obscured by DOM controls. Four production checks pass across Chromium and WebKit: circle-to-tooltip transit/dwell/leave/Escape, and dismissal while a file is selected with source/camera/focus invariants, including modal Escape priority. The existing accessibility/navigation suites also pass 17 Chromium/WebKit checks with one intentional Chromium-only touch-injection skip.

This closes the observed hover-content implementation defect. Human assistive-technology, text magnification and task-review gates above remain unclaimed.
