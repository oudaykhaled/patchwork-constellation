# DATA-05 / #10 — static inventory and import evidence

Implemented in `packages/analysis/src/static-graph.ts`, `imports.ts`, and `source-dependencies.ts`. Analysis reads pinned blobs and declarative manifests only. Repository scripts, dependencies, plugins, symlink targets, submodule repositories, and LFS payloads are never executed or followed.

| Acceptance criterion | Implementation and verification |
| --- | --- |
| Imports/re-exports/types/dynamic paths/aliases/workspaces | AST scan covers declarations, barrels, type-only specifiers, import types, import-equals, literal `import()` and unshadowed `require()`. Nonliteral imports, syntax errors and locally bound `require` report partial coverage. Directed circular/barrel fixture validates source path and line. Nearest-tsconfig scoping is preserved. Workspace exports support exact/wildcard subpaths and static types/import/require/node/default conditions; private/null/traversing paths are unresolved. |
| External/unresolved metadata | `node.externalImports` contains external/bare-specifier metadata; it creates no external circle. `node.unresolvedImports` and `importReasons` explain unresolved internal references. Unsupported tsconfig inheritance explicitly makes affected file coverage partial. |
| Context versus selected-head imports | Baseline edges carry `provenance:'context'` and pinned `snapshotSha`. `analyzeSourceDependencies` produces a distinct source-head layer with `sourceId`, `headSha`, `contextSha`, and per-source/per-file coverage. `enrichSelectedSourceDependencies` attaches this as `source.importEdges/importCoverage/importFiles`, leaving context edges, file facts and change counts untouched. Tests cover created/deleted files and independent layer failure. |
| Rename/ambiguous lineage | Footprint canonicalization is owned by DATA-04. Head-layer mapping uses `source.files` canonical IDs; unchanged targets are shared only when their blob hash matches context. An unproven target identity is omitted with a per-file reason, rather than merging unrelated same-path files. |
| Special/oversized files | Inventoried files expose `fileKind`, `fileMode`, `size`, `importCoverage`, and `importReasons`. Symlinks/submodules, generated/vendor/build files and sources over 80KB are excluded from parsing. Known binary extensions and NUL-containing source blobs are unsupported. Parsed LFS pointers are labeled and their payload is not fetched. Unknown non-JS/TS files remain visible with unsupported dependency extraction. Tests assert excluded files are never downloaded. |
| Parse caching | Bounded 500-entry cache contains syntax facts only, keyed by blob hash, content digest, script kind, TypeScript version, and resolver version. Config/path resolution runs against each current snapshot, avoiding stale resolved edges after config changes. Cached values are cloned; mutation/content-invalidation tests pass. |
| Per-file coverage | Every inventoried node has complete/partial/unsupported/excluded/failed coverage and explicit reasons; parse-budget omissions are partial. Source-head file coverage lives in `source.importFiles`. The inspector integration consumes these fields. |

## Integration contract

This change consumes DATA-06's `deriveRepositoryHierarchy/applyHierarchy` APIs. `buildStaticGraph` reads bounded package manifests and `.constellation.json`, applies validated explicit mappings or falls back with coverage reasons, and returns the versioned hierarchy/grouping revision. Analyzer version is exported as `ANALYZER_VERSION = 'static-v3'` and should be used by job idempotency keys.

DATA-04's extracted `footprints.ts` must call `await enrichSelectedSourceDependencies(result, kind, selection, options)` after canonical IDs/groups are established and before final snapshot validation. This hook and inspector coverage rendering are integrated by the parent workstream; this isolated commit does not duplicate the source-footprint loader. Source-head layers remain separate from baseline rendering to avoid presenting several branches as a merged code state.

Default source-head work is limited to three heads and 120 directly changed parsed files per request (40 each for three heads). Head inventory is bounded to 2,000 files and 20 declarative manifests per head. Exhaustion/fetch failure preserves exact footprints and the context map. This is an explicitly partial outgoing-import layer, not a full source-head runtime dependency graph. Additional requests can enrich later heads after cached layers are retained.

## Verification

On Windows, Node 24.22.1, pnpm 11.25.0, frozen offline install succeeded. `pnpm check` passed typechecking, **110 tests** (one optional PostgreSQL test skipped), and the production build. Final focused analysis suite: 28 tests.

Authoritative resolution reference: [TypeScript module reference](https://www.typescriptlang.org/docs/handbook/modules/reference.html#packagejson-exports), reviewed 2026-11-03. This resolver deliberately bounds declarative behavior; custom conditions, tsconfig inheritance/project references, compiler plugins and runtime-generated imports remain unsupported with visible coverage limitations.
